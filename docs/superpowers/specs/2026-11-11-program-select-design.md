# 실행 중인 프로그램 선택 — 설계

## 왜
지금 "표시할 앱" 목록은 Windows에 곡을 알려 준 앱만 보여 준다. 곡을 틀기 전에는 고를 수 없고, Windows에 곡을 안 알려 주는 프로그램은 위젯에 아예 못 띄운다. 실행 중인 프로그램을 직접 골라 두 경우를 모두 해결한다.

멜론과 TIDAL은 조사 결과 Windows에 곡을 정상으로 알려 준다. 이 기능은 그 밖의 프로그램(로컬 플레이어 등)을 위한 것이다.

## 사용자가 정한 것
- 두 방식을 모두 넣고 **프로그램별로 선택**한다: **Windows 곡 정보** / **창 제목**.
- 화면은 **기존 "표시할 앱" 목록에 통합**한다(방법 1).

## 목표가 아닌 것
- 프로그램 메모리를 읽거나 플레이어별 전용 연동을 만드는 것.
- 창 제목 방식에서 앨범 사진·재생 시간을 가져오는 것.
- 실행 중인 프로그램 전체를 목록에 자동으로 넣는 것(직접 고른 것만 들어간다).

## 방법 비교
1. **기존 목록에 통합 (선택됨)** — 켜고 끄는 곳이 한 군데라 초보자가 헷갈리지 않는다. 목록 화면을 조금 고쳐야 한다.
2. "창 제목으로 읽기" 칸을 따로 — 기존 동작을 안 건드려 안전하지만, 같은 프로그램이 두 칸에 나올 수 있다.

## 화면
- "표시할 앱" 목록 아래에 **실행 중인 프로그램 추가** 버튼. 누르면 창이 있는 프로그램 이름 목록이 펼쳐지고, 고르면 목록에 한 줄이 추가된다.
- 추가한 줄에는 켜기/끄기 체크, 읽는 방식 선택, 삭제 버튼이 있다.
- 읽는 방식이 "창 제목"이면 순서 선택이 나온다: **제목 - 아티스트** (기본) / **아티스트 - 제목**.
- 창 제목 방식을 고르면 짧은 안내: "앨범 사진과 재생 시간은 표시되지 않아요."
- Windows가 알려 준 기존 줄은 지금과 같다. 3개 언어 문구.

## 동작
- **저장**: settings.json의 새 필드 `Programs`(exe 이름 → 켜짐 여부, 방식, 순서). 기존 `Apps`는 그대로 둔다. 예전 설정 파일은 빈 목록으로 읽힌다.
- **실행 중인 프로그램 목록**: 보이는 창이 있는 프로세스의 exe 이름만, 중복 없이, 이름순. 이 프로그램 자신은 뺀다. 설정 페이지에 **창 제목은 보내지 않는다**(개인정보).
- **Windows 곡 정보 방식(미리 고르기)**: 처음 그 앱의 곡이 Windows에 잡힐 때, 이름이 맞는 추가 줄의 켜기/끄기 값으로 등록하고 그 줄은 기존 목록의 줄로 합친다. 이름 비교는 글자·숫자만 남겨 소문자로 만든 뒤, exe 이름이 앱 ID에 포함되는지로 본다(`Melon Player.exe` → `com.kakaoent.melon.player`).
- **창 제목 방식**:
  - 켜진 줄이 있을 때만 1초마다 해당 프로세스의 창 제목을 읽는다. 없으면 아무 일도 하지 않아 지금처럼 가볍다.
  - 제목을 ` - `로 나눠 순서 설정대로 제목/아티스트로 쓴다. ` - `가 없으면 전체를 제목으로 쓴다. 끝에 프로그램 이름이 붙어 있으면 뗀다.
  - 창 제목이 비었거나 프로그램 이름뿐이면 재생 중이 아니다.
  - **재생 여부**: 그 프로세스(같은 exe 이름의 자식 포함)가 실제로 소리를 내는지 Windows 오디오 세션으로 확인한다. 조용해지고 3초가 지나면 재생 중이 아니다. 오디오 정보를 못 읽으면 제목이 있을 때 재생 중으로 본다.
- **우선순위**: Windows에서 재생 중인 곡이 있으면 지금 규칙대로 그것을 쓴다. 없을 때만 창 제목 방식의 곡을 쓴다.
- 창 제목 곡은 앨범 사진·재생 시간 없이 위젯에 나온다(이미 있는 "사진 없음" 표시를 쓴다). 자동 색은 고른 색으로 돌아간다.

## 메모리 줄이기 (사용자 승인, 2026-11-11)
- 배포 exe의 단일 파일 압축을 끈다(`scripts/package.ps1`의 `EnableCompressionInSingleFile=false`). 실측(실행 45초 후, 재생 없음): 전용 메모리 약 83MB → 38MB, 작업 메모리 약 197MB → 107MB. 대신 exe가 76MB → 181MB로 커진다.
- .NET GC 설정(gcConcurrent, TieredPGO, GCgen0size, GCConserveMemory)은 실측에서 효과가 없어 넣지 않는다.
